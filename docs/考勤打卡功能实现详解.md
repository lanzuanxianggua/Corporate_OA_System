# 考勤打卡功能完整实现详解

## 整体流程概览

```
用户点击"上班打卡"按钮 → 前端 POST /api/attendance/clock-in → 后端拦截器校验(认证)
  → Controller 接收 → Service 业务逻辑（查今日记录→判断迟到→保存）
    → 返回 R.ok() → 前端更新页面状态
```

### 2. 状态码说明

| 状态值 | 含义 | 判定标准 |
|:---:|:---:|:---|
| **0** | 正常 | 上班打卡时间 ≤ 9:00，下班打卡时间 ≥ 18:00 |
| **1** | 迟到 | 上班打卡时间 > 9:00 |
| **2** | 早退 | 下班打卡时间 < 18:00 且上班状态为正常 |
| **3** | 缺勤 | 当日完全无打卡记录 |
| **4** | 休息 | 周末/节假日（系统标记） |
| **5** | 请假 | 审批通过后自动标记 |
| **6** | 出差 | 审批通过后自动标记 |

```typescript
const calcWorkHours = (clockIn?: string, clockOut?: string): string => {
    if (!clockIn || !clockOut) return "-";
    const start = dayjs(clockIn);
    const end = dayjs(clockOut);
    const diffMinutes = end.diff(start, "minute");   // 计算分钟差
    const hours = Math.floor(diffMinutes / 60);
    const minutes = diffMinutes % 60;
    return `${hours}h ${minutes}min`;
};
```

### 3. Service 层 — 核心业务逻辑

**文件**: `cn.oa.service.impl.AttendanceServiceImpl`

#### 3.1 上班打卡 (`clockIn`)

```java
private static final LocalTime NINE_OCLOCK = LocalTime.of(9, 0);   // 9:00 上班
private static final LocalTime SIX_OCLOCK  = LocalTime.of(18, 0);   // 18:00 下班

@Override
@Transactional
public void clockIn(Long empId) {
    // ① 查今天有没有打卡记录
    OaAttendance existing = getTodayAttendance(empId);
    LocalDateTime now = LocalDateTime.now();

    if (existing != null) {
        // ② 已有记录：检查是否重复点击
        if (existing.getClockIn() != null) {
            throw new BusinessException("今日已打卡");  // 防重复提交
        }
        // ③ 更新上班打卡时间
        existing.setClockIn(now);

        // ④ 判断是否迟到：当前时间 > 9:00
        if (now.toLocalTime().isAfter(NINE_OCLOCK)) {
            existing.setStatus(1);   // 迟到
        } else {
            existing.setStatus(0);   // 正常
        }
        this.updateById(existing);
        return;
    }

    // ⑤ 全新记录：创建一条新的考勤记录
    OaAttendance attendance = new OaAttendance();
    attendance.setEmpId(empId);
    attendance.setWorkDate(LocalDate.now());
    attendance.setClockIn(now);
    // 判断迟到
    attendance.setStatus(now.toLocalTime().isAfter(NINE_OCLOCK) ? 1 : 0);
    this.save(attendance);
}
```

**关键边界处理**：

| 场景 | 处理 | 说明 |
|:---|:---|:---|
| 第一次打卡 | 新建记录，状态根据时间判定 | 生成 `oa_attendance` 新行 |
| 已打卡再点 | `BusinessException("今日已打卡")` | 前端显示错误提示 |
| 9:00前打卡 | 状态=`0`（正常） | 8:59 打卡算正常 |
| 9:00:01打卡 | 状态=`1`（迟到） | 超过 9:00 一秒也算迟到 |
| 已标记"请假"后打卡 | 记录打卡时间，保留请假状态 | 请假期间实际有出勤的情况 |

#### 3.2 下班打卡 (`clockOut`)

```java
@Override
@Transactional
public void clockOut(Long empId) {
    // ① 获取今日记录
    OaAttendance attendance = getTodayAttendance(empId);

    // ② 检查有没有上班打卡
    if (attendance == null) {
        throw new BusinessException("今日未打卡，请先签到");
    }

    // ③ 检查是否已签退
    if (attendance.getClockOut() != null) {
        throw new BusinessException("今日已签退");
    }

    LocalDateTime now = LocalDateTime.now();
    attendance.setClockOut(now);

    // ④ 判断早退：当前时间 < 18:00 且上班状态不是迟到
    if (now.toLocalTime().isBefore(SIX_OCLOCK) && Integer.valueOf(0).equals(attendance.getStatus())) {
        attendance.setStatus(2);  // 早退
    }
    // 注意：如果是"迟到"状态（1），下班后不会替换为"早退"
    // 这样用户只会看到"迟到"而不是"迟到+早退"

    this.updateById(attendance);
}
```

**状态优先级逻辑**：

```
打卡情况                     → 最终状态
9:00前打卡 + 18:00后签退    → 0 (正常)
9:00后打卡 + 18:00后签退    → 1 (迟到)
9:00前打卡 + 18:00前签退    → 2 (早退)
9:00后打卡 + 18:00前签退    → 1 (迟到)  ← 不会覆盖为早退
全天未打卡                   → 无记录（由后台统计时标记为"缺勤"）
```

#### 3.5 管理员分页查询

```java
@Override
public IPage<Map<String, Object>> adminPage(int pageNum, int pageSize, String empName,
                                             Integer status, LocalDate startDate, LocalDate endDate) {
    // ① 如果有员工姓名筛选，先查到匹配的员工ID集合
    Set<Long> matchEmpIds = null;
    if (empName != null && !empName.isBlank()) {
        List<SysEmployee> matchedEmps = employeeMapper.selectList(
            new LambdaQueryWrapper<SysEmployee>()
                .like(SysEmployee::getEmpName, empName));
        if (matchedEmps.isEmpty()) return new Page<>(pageNum, pageSize); // 无匹配
        matchEmpIds = matchedEmps.stream().map(SysEmployee::getId).collect(Collectors.toSet());
    }

    // ② 拼接考勤查询条件
    LambdaQueryWrapper<OaAttendance> wrapper = new LambdaQueryWrapper<>();
    if (matchEmpIds != null)  wrapper.in(OaAttendance::getEmpId, matchEmpIds);
    if (status != null)       wrapper.eq(OaAttendance::getStatus, status);
    if (startDate != null)    wrapper.ge(OaAttendance::getWorkDate, startDate);
    if (endDate != null)      wrapper.le(OaAttendance::getWorkDate, endDate);
    wrapper.orderByDesc(OaAttendance::getWorkDate);

    // ③ 分页查询
    IPage<OaAttendance> page = this.page(new Page<>(pageNum, pageSize), wrapper);

    // ④ 批量关联员工信息（包含部门ID，供前端按部门筛选）
    // 使用批量查询而不是循环中逐条查，避免 N+1 问题
    Set<Long> neededEmpIds = page.getRecords().stream()
        .map(OaAttendance::getEmpId).collect(Collectors.toSet());
    List<SysEmployee> extraEmps = employeeMapper.selectBatchIds(neededEmpIds);
    Map<Long, SysEmployee> empMap = extraEmps.stream()
        .collect(Collectors.toMap(SysEmployee::getId, e -> e));

    // ⑤ 组装返回数据（员工姓名、部门ID等）
    List<Map<String, Object>> records = page.getRecords().stream().map(att -> {
        Map<String, Object> map = new LinkedHashMap<>();
        map.put("empName", empMap.get(att.getEmpId())?.getEmpName());
        map.put("deptId", empMap.get(att.getEmpId())?.getDeptId());
        map.put("workDate", att.getWorkDate());
        map.put("clockIn", att.getClockIn());
        map.put("clockOut", att.getClockOut());
        map.put("status", att.getStatus());
        return map;
    }).collect(Collectors.toList());
    ...
}
```

**为什么需要手动关联员工表，而不是直接用 SQL JOIN？**

因为 `oa_attendance` 只存 `emp_id`，不冗余员工姓名。如果直接用 MyBatis-Plus 的 `selectPage`，每行都去查员工表会出现 N+1 问题。这里的做法是：先查出所有考勤记录 → 收集所有 empId → 一次 `selectBatchIds` 查完所有员工 → 用 Map 关联。虽然代码量多一点，但性能更好。

## 四、请假/出差自动标记考勤

当员工的请假/出差审批通过后，系统会自动调用 `markLeaveAttendance()` 或 `markTripAttendance()`，在工作日自动填充考勤状态。

```java
@Override
@Transactional
public void markLeaveAttendance(Long empId, LocalDate startDate, LocalDate endDate) {
    markAutoAttendance(empId, startDate, endDate, 5, "请假自动标记");
}

@Override
@Transactional
public void markTripAttendance(Long empId, LocalDate startDate, LocalDate endDate) {
    markAutoAttendance(empId, startDate, endDate, 6, "出差自动标记");
}

private void markAutoAttendance(Long empId, LocalDate startDate, LocalDate endDate,
                                 int status, String remark) {
    // 遍历日期范围内的每一天（含起止日）
    for (LocalDate date = startDate; !date.isAfter(endDate); date = date.plusDays(1)) {
        // 跳过周末
        if (date.getDayOfWeek() == DayOfWeek.SATURDAY || date.getDayOfWeek() == DayOfWeek.SUNDAY) {
            continue;
        }
        // 查当日是否有记录
        OaAttendance existing = this.getOne(
            new LambdaQueryWrapper<OaAttendance>()
                .eq(OaAttendance::getEmpId, empId)
                .eq(OaAttendance::getWorkDate, date));
        if (existing == null) {
            // 无记录 → 新建一条
            OaAttendance attendance = new OaAttendance();
            attendance.setEmpId(empId);
            attendance.setWorkDate(date);
            attendance.setStatus(status);
            attendance.setRemark(remark);
            this.save(attendance);
        } else if (existing.getStatus() != null && existing.getStatus() == 3) {
            // 如果之前是"缺勤"状态 → 更新为请假/出差
            existing.setStatus(status);
            existing.setRemark(remark);
            this.updateById(existing);
        }
        // 如果已有打卡记录（status=0或1），则不覆盖
        // 因为员工可能实际出勤了，保留实际打卡数据
    }
}
```

**为什么要跳过周末？**
- 考勤系统只关心工作日，请假/出差审批天数也是按工作日计算
- 周末本来就不需要打卡，无需生成记录

**为什么不覆盖已有打卡记录？**
- 如果员工请了年假，但当天还是来公司上了半天班打了卡，保留实际打卡数据比覆盖为"请假"更准确

## 六、考勤状态联动机制

```
请假审批通过                出差审批通过
     ↓                          ↓
AttendanceService.markLeaveAttendance()   AttendanceService.markTripAttendance()
     ↓                          ↓
自动标记请假日期范围的工作日    自动标记出差日期范围的工作日
```

## 八、常见问题解答

### Q1：如果用户 9:00 整打卡，算迟到吗？
不算。迟到判定是 `isAfter()`，即严格大于 9:00。9:00 整打卡属于 `isAfter(9:00)` = false，状态为"正常"。

### Q2：如果用户打了上班卡但忘记打下班卡，会怎样？
下班打卡状态为 `null`，工作时长无法计算。系统在统计时可以将这类记录归类为"异常"（缺少签退），但不会自动标记为"早退"，因为没有足够证据。

### Q3：请假审批被拒绝了，考勤记录怎么处理？
审批驳回时，工作流回调被拒事件，触发 `removeMarkedAttendance()`，删除该时间内备注为"请假自动标记"的记录。记录的物理删除是安全的，因为这些记录本身也是自动生成的，不涉及真实打卡数据。

### Q4：周末打卡怎么处理？
系统默认不上班，但没有硬性限制。即便周末，用户也可以正常发起打卡请求。后台考勤组管理可以控制具体的排班规则。

### Q5：如果我上午请假、下午来上班了，怎么处理？
审批通过后系统会自动标记全天为"请假"。但如果员工又打了卡，`clockIn` 和 `clockOut` 时间会被记录，但状态会保留"请假"（请假标记不覆盖实际打卡记录）。管理员可在后台手动调整。
