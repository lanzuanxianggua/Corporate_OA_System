## 1. 环境要求

## 2. 快速启动（本地开发）

### 2.1 克隆项目并启动基础设施

```bash
# 克隆仓库（如果尚未克隆）
git clone <repository-url>
cd Corporate_OA_System

# 启动 MySQL + Redis（使用 Docker 方式）
docker compose -f docker/docker-compose.dev.yml up -d
```

如果不使用 Docker，请确保本地已安装并运行 MySQL 8.0+ 和 Redis 6+，并创建好数据库。

### 2.2 创建数据库

```sql
CREATE DATABASE IF NOT EXISTS oa_system
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;
```

### 2.3 启动后端

```bash
cd code/backend

# 编译 + 启动（首次启动会自动执行 Flyway 迁移）
mvn -pl oa-web -DskipTests spring-boot:run
```

### 2.4 启动前端

```bash
cd code/frontend
pnpm install
pnpm dev
```

### 2.5 验证启动

| 服务 | 访问地址 |
|------|---------|
| 前端页面 | http://localhost:8848 |
| 后端 API | http://localhost:8080 |
| Swagger 文档 | http://localhost:8080/doc.html |

### 2.6 登录系统

默认管理员账号：

| 工号 | 密码 | 角色 |
|------|------|------|
| `admin` | `123456` | 超级管理员 / 总经理 |

## 3. 后端部署详解

### 3.1 项目结构

```
code/backend/
├── pom.xml                  # 父 POM（聚合模块）
├── oa-common/               # 通用工具层
│   └── src/main/java/cn/oa/common/
│       ├── annotation/      # 自定义注解（@RequirePermission 等）
│       ├── config/          # WebMvcConfig、CORS 配置
│       ├── exception/       # 全局异常体系
│       ├── interceptor/     # AuthInterceptor、RateLimitInterceptor
│       ├── resolver/        # PermissionResolver、RoleResolver 接口
│       ├── result/          # R<T> 统一响应封装
│       ├── utils/           # JWT、IP、Web 工具类
│       └── service/         # RedisService
├── oa-model/                # 数据模型层
│   └── src/main/java/cn/oa/
│       ├── entity/          # 48个数据库实体
│       ├── dto/             # 21个入参 DTO
│       └── vo/              # 14个出参 VO
├── oa-mapper/               # 持久层
│   └── src/main/java/cn/oa/mapper/  # 48个 MyBatis-Plus Mapper
├── oa-service/              # 业务逻辑层
│   └── src/main/java/cn/oa/service/
│       ├── impl/            # Service 实现
│       └── workflow/        # 工作流引擎
└── oa-web/                  # 控制层 + 配置
    └── src/main/
        ├── java/cn/oa/
        │   ├── controller/  # 36个 REST Controller
        │   ├── config/      # MyBatis-Plus 配置、Flyway 配置
        │   └── aspect/      # AOP 操作日志切面
        └── resources/
            ├── application.yml       # 本地开发配置
            ├── application-ci.yml    # CI 测试配置
            ├── application-prod.yml  # 生产环境配置
            └── db/migration/         # Flyway 迁移脚本
```

### 3.2 编译打包

```bash
cd code/backend

# 全量编译（不跑测试）
mvn -DskipTests compile

# 打包为可执行 JAR
mvn -DskipTests package -pl oa-web -am

# 打包产物位置
ls oa-web/target/oa-web-*.jar
```

### 3.3 启动方式

**方式一：Maven 直接启动（开发推荐）**
```bash
mvn -pl oa-web -DskipTests spring-boot:run
```

**方式二：JAR 包运行（生产部署）**
```bash
java -jar oa-web/target/oa-web-1.0.0.jar \
  --spring.profiles.active=prod
```

### 3.4 关键配置说明

数据库连接（`application.yml`）：
```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/oa_system?useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: oa_v2
    password: oa_v2
  data:
    redis:
      host: 127.0.0.1
      port: 6379
      database: 0
```

> ⚠️ **重要**：数据库连接 URL **必须**使用 `127.0.0.1`，**禁止**使用 `localhost`（避免 Windows IPv6 慢解析）。
> 
> ⚠️ **CORS 注意事项**：Spring 6 严格匹配 origin，`localhost` 和 `127.0.0.1` 被视为不同来源。前端访问地址必须与后端 CORS 白名单配置一致。

### 3.5 环境 Profile

| Profile | 用途 | 数据库 |
|---------|------|--------|
| `default` (无) | 本地开发 | `oa_system`（127.0.0.1:3306） |
| `ci` | CI 自动化测试 | `oa_system_test` |
| `prod` | 生产环境 | 生产数据库 |

### 3.6 内存优化

生产部署 JVM 参数建议：
```bash
java -jar oa-web/target/oa-web-1.0.0.jar \
  -Xms512m -Xmx1024m \
  -XX:+UseG1GC \
  -Dspring.profiles.active=prod
```

```bash
cd code/frontend
pnpm build
# 产物输出到 dist/ 目录
```

### 4.4 部署到 Nginx

将 `dist/` 目录部署到 Nginx，示例配置：

```nginx
server {
    listen 80;
    server_name oa.example.com;

    # 前端静态文件
    root /var/www/oa-system/dist;
    index index.html;

    # SPA 路由 fallback
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理到后端
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    
    # WebSocket 代理
    location /ws/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

### 4.5 前端特性说明

- **自动导入**：Vue API、Vue Router、Pinia 和 Element Plus 组件无需手动 import
- **路径别名**：使用 `@/` 代替 `src/`
- **Vite 代理**：开发环境下 `/api`、`/user`、`/role` 等路径自动代理到 `http://localhost:8080`（见 `vite.config.ts` 的 `server.proxy` 配置）
- **CSS 方案**：Tailwind CSS v4（CSS-first 配置，`@tailwindcss/vite`）
- **类型安全**：`vue-tsc -b` 严格模式类型检查（`"strict": true`）
- **Chunk 分离**：Vue/Router/Pinia → `vue` chunk，Element Plus → `element` chunk，echarts → `echarts` chunk

RestartSec=10

## 7. 数据库初始化与迁移

### 7.1 数据库初始化

**方式一：从完整备份恢复（推荐）**
```bash
mysql -h 127.0.0.1 -u oa_v2 -p oa_system < sql/oa_system_dump.sql
```

**方式二：Flyway 自动迁移**
Spring Boot 启动时 Flyway 自动执行 `db/migration/` 目录下的迁移脚本。首次启动会自动建表。

**方式三：手动建表**
执行 `db/business_schema.sql` 中的建表语句，然后启动应用让 Flyway 补充工作流相关表。

### 7.2 Flyway 迁移脚本规则

- 文件名格式：`V<version>__<description>.sql`（双下划线）
- 当前最新版本：V1013
- 新增脚本从 V1014 开始
- 存放位置：`code/backend/oa-web/src/main/resources/db/migration/`

### 7.3 迁移冲突处理

```bash
# 查看已执行的迁移
mysql -h 127.0.0.1 -u oa_v2 -p oa_system \
  -e "SELECT version, description, installed_on FROM flyway_schema_history ORDER BY installed_rank DESC;"

# 清理迁移历史（⚠️ 仅限开发环境）
mysql -h 127.0.0.1 -u oa_v2 -p oa_system \
  -e "DROP TABLE IF EXISTS flyway_schema_history;"
```

## 8. 常见问题排查

### 8.1 后端无法启动

**"Mapper not found" 错误**
```bash
# 重新安装 Mapper 和 Model 模块
mvn -pl oa-mapper,oa-model -am -DskipTests install
```

**端口被占用**
```bash
# 查看 8080 端口占用
MSYS_NO_PATHCONV=1 netstat -ano | grep 8080
# 强制杀进程
MSYS_NO_PATHCONV=1 taskkill /F /PID <pid>
```

### 8.2 前端跨域错误（CORS）

- Vite 开发模式下大部分 API 通过代理转发，不触发 CORS
- 直接访问后端 API 时才会触发
- 后端 CORS 配置在 `WebMvcConfig.java`，已放行 `localhost:*`、`127.0.0.1:*` 及 `10.*`、`192.168.*`、`172.*` 局域网段

### 8.3 Docker MySQL 无法连接

```bash
# 检查容器状态
docker compose -f docker/docker-compose.dev.yml ps

# 查看日志
docker compose -f docker/docker-compose.dev.yml logs mysql

# 重启容器
docker compose -f docker/docker-compose.dev.yml restart mysql
```

### 8.4 Windows Git Bash 注意事项

| 问题 | 解决方法 |
|------|---------|
| docker exec 路径解析失败 | 命令前加 `MSYS_NO_PATHCONV=1` |
| Maven 中文日志乱码 | grep 加 `-a` 参数 |
| 端口占用无法诊断 | `MSYS_NO_PATHCONV=1 netstat -ano \| grep 8080` |
| 进程杀不掉 | `MSYS_NO_PATHCONV=1 taskkill /F /PID <pid>` |
