# 消息功能完整实现详解

## 整体流程概览

```
发消息: 管理员选择接收人 → 填写标题+内容 → POST /api/message/send → 存入 oa_message 表
收消息: 接收人打开消息中心 → GET /api/message/page → 列表展示
实时推送: 新消息到达 → WebSocket 推送通知 → 顶部未读数字更新
标记已读: 用户点击消息 → POST /api/message/{id}/read → isRead=0→1
```

---

## 一、数据库设计

### 1. 消息表 `oa_message`

**文件**: `cn.oa.entity.OaMessage`

```java
@Data
@TableName("oa_message")
public class OaMessage {

    @TableId(type = IdType.AUTO)
    private Long id;                 // 主键，自增

    private Long senderId;           // 发送人ID（关联 sys_employee.id）

    private Long receiverId;         // 接收人ID（关联 sys_employee.id）

    @TableField(exist = false)
    private Integer msgType;         // 消息类型（非数据库字段，扩展用）

    private String title;            // 消息标题

    private String content;          // 消息内容

    private Integer isRead = 0;      // 是否已读：0=未读 1=已读

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime; // 发送时间（自动填充）

    @TableField(exist = false)
    private String senderName;       // 发送人姓名（非数据库字段，查询时填充）
}
```

### 2. DDL 语句

```sql
CREATE TABLE oa_message (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '主键',
    sender_id   BIGINT       NOT NULL COMMENT '发送人ID',
    receiver_id BIGINT       NOT NULL COMMENT '接收人ID',
    title       VARCHAR(128)          COMMENT '消息标题',
    content     TEXT                  COMMENT '消息内容',
    is_read     INT DEFAULT 0        COMMENT '0=未读 1=已读',
    del_flag    VARCHAR(2) DEFAULT '0' COMMENT '逻辑删除',
    create_by   VARCHAR(64)          COMMENT '创建人',
    update_by   VARCHAR(64)          COMMENT '更新人',
    create_time DATETIME             COMMENT '发送时间',
    update_time DATETIME             COMMENT '修改时间',
    -- 索引
    INDEX idx_receiver (receiver_id, is_read),   -- 接收人查未读消息
    INDEX idx_receiver_time (receiver_id, create_time DESC) -- 消息列表排序
);
```

### 3. 设计要点

| 设计决策 | 原因 |
|:---|:---|
| `sender_id` 存 ID 而非姓名 | 不冗余员工信息，员工改名不影响历史消息 |
| `senderName` 用 `@TableField(exist = false)` | 只用于前端展示，数据库不存 |
| `isRead` 用 `0/1` 数字而非时间戳 | 简单高效，查未读数直接 COUNT |
| `content` 用 TEXT 类型 | 消息可能较长，TEXT 支持 65KB |
| 无外键约束 | 人员删除后消息仍需保留（业务日志价值） |

## 三、后端实现

### 1. 请求链路

```
前端 POST /api/message/send
  → AuthInterceptor（解析 JWT，校验 ADMIN 角色）
    → MessageController.send()
      → MessageService.send(message)
        → this.save(message)  →  INSERT INTO oa_message
          → 返回 R.ok()
```

### 2. Controller 层

**文件**: `cn.oa.controller.MessageController`

```java
@Slf4j
@RestController
@RequestMapping("/api/message")
@Tag(name = "消息管理")
public class MessageController {

    @Autowired
    private MessageService messageService;

    /**
     * 获取未读消息数量
     * 前端顶部导航栏定时调用，显示小红点
     */
    @GetMapping("/unread-count")
    public R<Long> unreadCount(HttpServletRequest request) {
        Long empId = WebUtil.getEmpId(request);
        Long count = messageService.getUnreadCount(empId);
        return R.ok(count);
    }

    /**
     * 分页查询消息列表
     * 支持分页，按时间倒序
     */
    @GetMapping("/page")
    public R<PageResult<OaMessage>> page(
            @RequestParam(defaultValue = "1") int pageNum,
            @RequestParam(defaultValue = "10") int pageSize,
            HttpServletRequest request) {
        Long empId = WebUtil.getEmpId(request);
        IPage<OaMessage> page = messageService.pageList(pageNum, pageSize, empId);
        return R.ok(PageResult.of(page.getTotal(), page.getRecords()));
    }

    /**
     * 发送消息
     * 只有 ADMIN 角色可以发送（@RequireAdmin）
     */
    @PostMapping("/send")
    @RequireAdmin                                // ← 权限控制：仅管理员
    @OperationLog(module = "消息管理", operation = "发送消息")  // ← AOP 操作日志
    public R<Void> send(@RequestBody @Valid OaMessage message, HttpServletRequest request) {
        Long empId = WebUtil.getEmpId(request);   // 从 JWT 获取发送人
        message.setSenderId(empId);                // 自动填充发送人

        if (message.getReceiverId() == null) {
            return R.fail("请输入接收人ID");
        }

        messageService.send(message);
        log.info("Message sent: from={}, to={}", empId, message.getReceiverId());
        return R.ok();
    }

    /**
     * 标记消息已读
     * 检查消息接收人是否为当前用户，防止越权
     */
    @PostMapping("/{id}/read")
    public R<Void> markAsRead(@PathVariable Long id, HttpServletRequest request) {
        Long empId = WebUtil.getEmpId(request);

        // 验证消息接收人权限
        OaMessage message = messageService.getById(id);
        if (message == null) return R.fail("消息不存在");
        if (!message.getReceiverId().equals(empId)) return R.fail("无权操作此消息");

        messageService.markAsRead(id, empId);
        return R.ok();
    }
}
```

### 4. Service 层

**文件**: `cn.oa.service.impl.MessageServiceImpl`

```java
@Service
public class MessageServiceImpl extends ServiceImpl<OaMessageMapper, OaMessage> implements MessageService {

    @Autowired
    private SysEmployeeMapper employeeMapper;

    /** ======== 1. 发送消息 ======== */
    @Override
    @Transactional
    public void send(OaMessage message) {
        // ① 参数校验
        if (message.getReceiverId() == null) {
            throw new BusinessException("接收人不能为空");
        }
        if (message.getContent() == null || message.getContent().isBlank()) {
            throw new BusinessException("消息内容不能为空");
        }

        // ② 设置默认值
        message.setIsRead(0);   // 新消息默认未读

        // ③ 持久化保存
        this.save(message);
    }

    /** ======== 2. 标记已读 ======== */
    @Override
    @Transactional
    public void markAsRead(Long msgId, Long empId) {
        LambdaUpdateWrapper<OaMessage> wrapper = new LambdaUpdateWrapper<>();
        wrapper.eq(OaMessage::getId, msgId)
               .eq(OaMessage::getReceiverId, empId)   // 只能标记自己的消息
               .set(OaMessage::getIsRead, 1);          // 0→1
        boolean ok = this.update(wrapper);
        if (!ok) {
            throw new BusinessException("消息不存在或无权操作");
        }
    }

    /** ======== 3. 获取未读数量 ======== */
    @Override
    public Long getUnreadCount(Long empId) {
        // SELECT COUNT(*) FROM oa_message WHERE receiver_id=? AND is_read=0 AND del_flag='0'
        LambdaQueryWrapper<OaMessage> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(OaMessage::getReceiverId, empId)
               .eq(OaMessage::getIsRead, 0);
        return this.count(wrapper);
    }

    /** ======== 4. 分页查询消息列表 ======== */
    @Override
    public IPage<OaMessage> pageList(int pageNum, int pageSize, Long receiverId) {
        Page<OaMessage> page = new Page<>(pageNum, pageSize);
        LambdaQueryWrapper<OaMessage> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(OaMessage::getReceiverId, receiverId)  // 只看自己的消息
               .orderByDesc(OaMessage::getCreateTime);     // 最近的在最前
        IPage<OaMessage> result = this.page(page, wrapper);

        // ★ 批量填充 senderName（发送人姓名）
        // 避坑：oa_message 表只存 sender_id，不冗余姓名
        // 如果逐条查 employee 表会 N+1 查询，所以一次性查完所有发送人
        List<Long> senderIds = result.getRecords().stream()
                .map(OaMessage::getSenderId)
                .filter(Objects::nonNull)
                .distinct()
                .collect(Collectors.toList());

        if (!senderIds.isEmpty()) {
            List<SysEmployee> senders = employeeMapper.selectBatchIds(senderIds);  // 批量查
            Map<Long, String> senderMap = senders.stream()
                    .collect(Collectors.toMap(SysEmployee::getId, SysEmployee::getEmpName));

            result.getRecords().forEach(msg ->
                msg.setSenderName(senderMap.getOrDefault(msg.getSenderId(), "")));
        }
        return result;
    }
}
```

**为什么用 `LambdaUpdateWrapper` 而不用 `updateById` 标记已读？**
- `updateById` 需要先 `selectById` 查出来再 `update`，涉及两次 SQL 操作
- `LambdaUpdateWrapper` 直接用 `set(isRead, 1)` 只发送一次 UPDATE，更高效
- 同时还附加了 `receiverId` 条件，防止越权（用户 A 不能标记用户 B 的消息为已读）

## 四、未读数实时推送（WebSocket 联动）

### 1. WebSocket 服务端

**文件**: `cn.oa.config.WebSocketConfig`

```java
@Configuration
@EnableWebSocket
public class WebSocketConfig implements WebSocketConfigurer {

    @Bean
    public NotificationEndpoint notificationEndpoint() {
        return new NotificationEndpoint();
    }

    @Override
    public void registerWebSocketHandlers(WebSocketHandlerRegistry registry) {
        registry.addHandler(notificationEndpoint(), "/ws/notification")
                .setAllowedOrigins("http://localhost:8848", "http://localhost:5173")
                .addInterceptors(new HttpSessionHandshakeInterceptor());
    }
}
```

### 2. 前端未读数实时更新机制

```
时序说明：

① 管理员发送消息 → POST /api/message/send → 存入数据库
  → 后端触发 WebSocket 消息推送
    → 在线接收人 WebSocket 收到 {"type": "NEW_MESSAGE", "unreadCount": 5}
      → 前端顶部导航栏未读数即时更新 +1

② 用户标记已读 → POST /api/message/{id}/read
  → 前端即时更新本地状态
    → 同时重新请求 GET /api/message/unread-count 确认

③ 定时轮询保底（每 60 秒）
  → 防止 WebSocket 断连后未读数不更新
  → 确保未读数始终正确
```

### 3. 前端顶部未读数的显示

**文件**: 布局组件（通常是 `topbar` 或 `navbar`）

```typescript

// 初始获取

    const res = await getUnreadCount();
    unreadCount.value = res.data || 0;
};

// WebSocket 收到新消息时
ws.onmessage = (event) => {
    const data = JSON.parse(event.data);
    if (data.type === "NEW_MESSAGE") {
```

## 五、消息通知与其他通知渠道的关系

本项目有 3 种通知渠道，各自分工不同：

| 渠道 | 数据表 | 触发方式 | 实时性 | 持久性 | 用途 |
|:---|:---|:---:|:---:|:---:|:---|
| **内部消息** | `oa_message` | 管理员手动发送 | 中 | ✅ 数据库持久化 | 点对点沟通、通知 |
| **系统待办** | `oa_todo` | 工作流自动生成 | 中 | ✅ 数据库持久化 | 待审批任务、系统通知 |
| **WebSocket** | 内存 | 事件驱动 | ⭐⭐⭐ 即时 | ❌ 不持久 | 实时推送未读数变化 |

**三者的协作关系**：
```
新消息到达 → 存入 oa_message → WebSocket 推送通知
  → 用户看到顶部红点 → 打开消息列表 → 点开详情 → 标记已读
  → 未读数 -1 → WebSocket 同步到前端
```

## 七、安全设计

| 安全措施 | 实现 | 说明 |
|:---|:---|:---|
| **发送权限** | `@RequireAdmin` | 只有管理员能发送消息 |
| **查看权限** | `receiverId = 当前用户` | 只能看自己的消息列表 |
| **标记已读权限** | `message.receiverId.equals(empId)` | 不能标记别人的消息为已读 |
| **JWT 认证** | `AuthInterceptor` | 所有接口必须先登录 |
| **数据隔离** | WHERE + `receiverId` | 数据库层确保只能查自己 |

## 八、涉及技术点总结

| 技术 | 应用场景 |
|:---|:---|
