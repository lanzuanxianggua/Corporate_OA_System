登录功能完整实现

  整体流程概览

  ① 用户输入账号密码 → ② 获取图形验证码 → ③ 点击登录 → ④ 后端验证
  → ⑤ 生成 JWT Token → ⑥ 存 Redis → ⑦ 返回登录信息 → ⑧ 前端跳转首页

  下面逐步拆解每一环节。

  ---
  步骤 1：用户打开登录页

  文件: code/frontend/src/views/login/index.vue

  页面分为左右两栏：
  - 左侧（灰白渐变）：卡通动画角色区域，4个角色（Purple、Black、Orange、Yellow）的眼球会跟随鼠标移动
  - 右侧（深色背景）：登录表单

  其中，Pupil（瞳孔）和 EyeBall（眼球）是封装好的 Vue 组件，通过在 onMounted 中注册全局的 mousemove 事件监听器来跟踪鼠标位置，再利用 computed 计算瞳孔的偏移量并应用 transform:
  translate() 实现动画。

  打开页面时，onMounted 触发三件事：
  1. 注册鼠标追踪
  2. 启动 Purple 和 Black 的随机眨眼定时器（每隔 3-7 秒眨眼一次，持续 150ms）
  3. 请求图形验证码

  步骤 2：获取图形验证码

  请求链路：
  前端 GET /api/auth/captcha → 后端 CaptchaUtil.generate() → 返回 Base64 图片 + uuid

  后端代码 - 文件: cn.oa.controller.AuthController

  验证码生成工具 - 文件: cn.oa.common.utils.CaptchaUtil

  public static CaptchaResult generate(RedisService redisService) {
      // 1. 生成 4 位随机数字
      String code = String.format("%04d", (int)(Math.random() * 10000));
      // 2. 生成唯一标识 UUID
      String uuid = UUID.randomUUID().toString().replace("-", "");
      // 3. 将验证码存入 Redis，key="captcha:"+uuid，5分钟过期
      redisService.set("captcha:" + uuid, code, 300);
      // 4. 把验证码画成图片，转 Base64 编码
      String imgBase64 = generateBase64Image(code);
      // 5. 返回 uuid（用于提交验证）+ 图片数据（用于前端显示）
      return new CaptchaResult(uuid, imgBase64);
  }

  前端接收 - 文件: code/frontend/src/views/login/index.vue

  const refreshCaptcha = async () => {
      const res = await getCaptcha();
      captchaImg.value = res.data.img;       // Base64 图片，直接给 <img :src="captchaImg">

  关键点：为什么要用 uuid + code 两段式设计？验证码图片在浏览器上展示给用户看，用户输入的是 code，但提交时要把 uuid 也带回后端。后端通过 uuid 从 Redis 中取出正确的 code
  进行比对，防止验证码被篡改。

  步骤 5：后端拦截器链

  请求到达后端后，先经过 Servlet Filter，然后进入 Spring 拦截器链：

  5.1 限流拦截器

  文件: cn.oa.common.interceptor.RateLimitInterceptor

  public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
      String ip = IpUtil.getClientIp(request);
      String key = "rate:login:" + ip;

      long count = redisService.increment(key);     // Redis INCR 命令
      if (count == 1) {
          redisService.expire(key, 60, TimeUnit.SECONDS); // 设置 60 秒过期
      }
      if (count > 5) {  // 同一 IP 每分钟超过 5 次
          response.setStatus(429);
          response.getWriter().write("{\"code\":429,\"message\":\"请求过于频繁\"}");
          return false;  // 拦截
      }
      return true;  // 放行
  }

  这里利用了 Redis INCR 原子操作：首次请求 key 不存在 → INCR 返回 1 → 设置过期时间 60 秒。后续请求递增计数，超过 5 次就限流。如果用户暴力破解密码，60 秒内最多试 5 次。

  @PostMapping({"/login", "/api/auth/login"})
  @OperationLog(module = "认证管理", operation = "用户登录")
  public R<LoginVO> login(@RequestBody @Valid LoginDTO dto, HttpServletRequest request) {
      // ① 校验验证码
      if (!CaptchaUtil.verify(redisService, dto.getCaptchaUuid(), dto.getCaptchaCode())) {
          return R.fail("验证码错误或已过期");

      LoginVO vo = authService.login(dto.getUsername(), dto.getPassword(), request);
      log.info("User logged in: username={}", dto.getUsername());
      return R.ok(vo);
  }

  验证码校验逻辑：

  public static boolean verify(RedisService redisService, String uuid, String code) {
      if (uuid == null || code == null) return false;
      String key = "captcha:" + uuid;
      String stored = redisService.get(key);   // 从 Redis 取出
      redisService.delete(key);                // 一次性使用，立即删除（防止重复利用）
      return stored != null && stored.equalsIgnoreCase(code);  // 忽略大小写比对
  }

  验证码是一次性的：
  - 验证完成后立即从 Redis 删除，防止同一验证码被重复使用
  - 登录失败刷新验证码时，旧的 uuid 自动过期（5 分钟），无法再利用

  步骤 7：Service 层 — 核心业务逻辑

  文件: cn.oa.service.impl.AuthServiceImpl 的 login() 方法

  public LoginVO login(String username, String password, HttpServletRequest request) {
      // ① 根据用户名查询员工
      LambdaQueryWrapper<SysEmployee> wrapper = new LambdaQueryWrapper<>();
      wrapper.eq(SysEmployee::getEmpCode, username);
      SysEmployee employee = employeeMapper.selectOne(wrapper);

      // ② 检查用户是否存在
      if (employee == null) {
          recordLoginLog(null, username, request, 0, "用户名不存在");
          throw new BusinessException("用户名不存在");
      }

      // ③ BCrypt 比对密码（BCrypt 是单向哈希，不能解密，只能用 checkpw 比对）
      if (!BCrypt.checkpw(password, employee.getPassword())) {
          recordLoginLog(employee.getId(), username, request, 0, "密码错误");
          throw new BusinessException("密码错误");
      }

      // ④ 检查是否被逻辑删除或禁用
      if ("1".equals(employee.getDelFlag())) {
          throw new BusinessException("该账号已被禁用");
      }
      if (employee.getStatus() == null || employee.getStatus() == 0) {
          throw new BusinessException("该账号已被禁用");
      }

  关于 BCrypt：用户的密码在注册/管理员添加时经过 BCrypt.hashpw(password) 加密存储。BCrypt 的特点：
  - 每次哈希结果都不同（内置随机 salt）
  - 无法反向解密
  - 验证只能用 BCrypt.checkpw(明文, 哈希值)，由 BCrypt 库从哈希中提取 salt 重新计算比对

  注册时：password "123456" → BCrypt.hashpw() → "$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy"
  登录时：输入 "123456" → BCrypt.checkpw("123456", 数据库中的hash) → true/false

      // ⑤ 查询用户的角色列表
      LambdaQueryWrapper<SysEmpRole> empRoleWrapper = new LambdaQueryWrapper<>();
      empRoleWrapper.eq(SysEmpRole::getEmpId, employee.getId());
      List<SysEmpRole> empRoles = empRoleMapper.selectList(empRoleWrapper);

      List<String> roleKeys = new ArrayList<>();
      if (!empRoles.isEmpty()) {
          List<Long> roleIds = empRoles.stream()
              .map(SysEmpRole::getRoleId)
              .collect(Collectors.toList());
          List<SysRole> roles = roleMapper.selectBatchIds(roleIds);
          roleKeys = roles.stream()
              .map(SysRole::getRoleKey)
              .collect(Collectors.toList());
      }
      if (roleKeys.isEmpty()) {
          roleKeys.add("USER");  // 至少有一个基础角色
      }

  权限查询链路：sys_employee → sys_emp_role（多对多关联表）→ sys_role → 取出 role_key

      // ⑥ 生成 JWT Token
      String token = jwtUtil.generateToken(employee.getId(), employee.getEmpName());

      // ⑦ Token + 角色信息存入 Redis
      redisTemplate.opsForValue().set("token:" + employee.getId(), token, 7200, TimeUnit.SECONDS);
      redisTemplate.opsForValue().set("roles:" + employee.getId(), roleKeys, 7200, TimeUnit.SECONDS);

      // ⑧ 记录在线用户
      String ip = IpUtil.getClientIp(request);
      onlineUserService.userLogin(employee.getId(), employee.getEmpName(), ip, browser);

      // ⑨ 记录登录日志（IP、浏览器、操作系统、时间）
      recordLoginLog(employee.getId(), username, request, 1, "登录成功");

      // ⑩ 组装返回数据
      LoginVO vo = new LoginVO();
      vo.setAccessToken(token);                    // JWT Token
      vo.setRefreshToken(token);                   // 刷新用 Token
      vo.setExpires("2026/06/16 22:00:00");        // 过期时间
      vo.setUsername(employee.getEmpCode());        // 员工编号
      vo.setNickname(employee.getEmpName());        // 员工姓名
      vo.setAvatar(employee.getAvatar() != null ? employee.getAvatar() : "");
      vo.setRoles(roleKeys);                        // 角色列表
      vo.setPermissions(resolvePermissions(roles, roleKeys)); // 权限码列表
      return vo;
  }

  步骤 8：JWT Token 生成

  文件: cn.oa.common.utils.JwtUtil

  @Component
  public class JwtUtil {

      private static final long EXPIRATION = 7200L;  // 2 小时
      private final SecretKey signingKey;

      public JwtUtil(@Value("${jwt.secret}") String secret) {
          // 从 application.yml 读取密钥，用 HMAC-SHA256 算法签名
          this.signingKey = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
      }

      public String generateToken(Long empId, String empName) {
          Date now = new Date();
          Date expiration = new Date(now.getTime() + EXPIRATION * 1000);  // 2小时后

          return Jwts.builder()
              .claim("empId", empId)         // 自定义声明：员工ID
              .claim("empName", empName)     // 自定义声明：员工姓名
              .issuedAt(now)                 // 签发时间
              .expiration(expiration)        // 过期时间
              .signWith(signingKey, Jwts.SIG.HS256)  // HMAC-SHA256 签名
              .compact();
      }
  }

  步骤 11：后续请求自动携带 Token

  此后，该用户的所有 API 请求，都会通过 axios 请求拦截器 自动在 Authorization 头携带 JWT Token：

  request.interceptors.request.use((config) => {

  后端 AuthInterceptor 对每个请求（登录等白名单路径除外）都会：
  1. 从请求头拿到 Token
  2. 解析 JWT 获取 empId
  3. 查 Redis 核对 Token 是否有效（未被管理员踢下线）
  4. 将用户信息放入 UserContext（ThreadLocal），供业务代码随时获取
