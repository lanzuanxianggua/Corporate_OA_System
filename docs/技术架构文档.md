### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **分层职责清晰** | Controller → Service → Mapper 严格分层，禁止跨层调用 |
| **轻量无侵入** | 无 Spring Security/Shiro，自研 JWT + Filter + Interceptor |
| **事件驱动解耦** | Spring Event 替代 MQ，工作流回调与通知发送解耦 |
| **约定大于配置** | MyBatis-Plus 注解 SQL，无 XML；统一响应格式 `R<T>` |
| **缓存优先** | Redis 缓存角色、权限、部门树、在线用户 |
| **自研工作流** | 图结构定义 + 迭代式路由引擎，支持复杂分级审批 |

### 2.4 Controller 层设计

每个 Controller 对应一个业务域，职责：

```java
@RestController
@RequestMapping("/api/leave")
@Tag(name = "请假管理")
public class LeaveApplyController {

    @PostMapping("/submit")
    @Operation(summary = "提交请假申请")     // Swagger 文档
    @OperationLog(module = "请假管理", operation = "提交")  // 操作日志
    public R<Void> submit(@RequestBody @Valid OaLeaveApply apply, HttpServletRequest request) {
        // 1. 从请求属性获取当前用户
        Long empId = WebUtil.getEmpId(request);
        // 2. 调用 Service 层（不包含任何业务逻辑）
        leaveApplyService.submit(apply, empId);
        // 3. 返回统一响应
        return R.ok();
    }
}
```

- 使用 `@Validated` / `@Valid` 自动参数校验
- 使用 `@RequirePermission` / `@RequireRole` 控制访问权限
- 统一返回 `R<T>` 格式（code/message/data）

### 2.5 Service 层设计

```java
public interface LeaveApplyService {
    void submit(OaLeaveApply apply, Long empId);
    void approve(ApproveDTO dto, Long approverId);
    IPage<OaLeaveApply> myApplies(Long empId, int pageNum, int pageSize);
}

@Service
@Transactional  // 事务边界在 Service 层
public class LeaveApplyServiceImpl extends BaseApprovalServiceImpl<OaLeaveApply> {
    @Override
    protected Map<String, Object> buildConditionContext(OaLeaveApply entity) {
        return Map.of("days", entity.getLeaveDays());
    }
}
```

- 写操作和复杂业务逻辑**必须**在 Service 层
- `@Transactional` 声明事务边界
- 继承 `BaseApprovalServiceImpl` 复用工作流集成逻辑

## 4. 工作流引擎架构

### 4.1 引擎概述

自研工作流引擎，支持多版本 Schema 定义和图结构路由。

### 4.2 核心组件

```
┌──────────────────────────────────────────────────┐
│                   WorkflowController              │
├──────────────────────────────────────────────────┤
│                  WorkflowService                  │
├─────────┬──────────┬──────────┬───────────────────┤
│ 流程定义   │ 流程实例  │ 任务管理  │  审批人解析       │
│ 管理      │ 启动/路由 │ 处理/转办 │  assigneeResolver │
├─────────┴──────────┴──────────┴───────────────────┤
│              WorkflowRuntimeEngine                │
│    (图解析 → 条件评估 → 路径扁平化 → 节点调度)      │
├──────────────────────────────────────────────────┤
│           WorkflowCallbackDispatcher             │
│       (Spring Event: onApproved / onRejected)     │
└──────────────────────────────────────────────────┘
```

### 4.3 数据模型

```
wf_process_definition       # 流程定义（node_config 存储 JSON 图结构）
wf_process_instance          # 流程实例（一次运行）
wf_task                      # 任务节点（审批任务实例）
wf_cc_record                 # 抄送记录
wf_delegation                # 审批委托
```

### 4.4 流程定义 Schema

**v3 图结构（当前主要版本）**：

```json
{
  "schemaVersion": 3,
  "nodes": [
    {"nodeId": "start", "nodeType": "start", "nodeName": "开始"},
    {"nodeId": "n_manager", "nodeType": "approval", "nodeName": "部门经理审批",
     "assigneeType": "dept_manager", "assigneeValue": "dept_manager",
     "timeoutHours": 24, "timeoutAction": "escalate",
     "escalateTo": {"type": "role_global", "value": "DIRECTOR"}},
    {"nodeId": "gw_days", "nodeType": "gateway", "gatewayType": "exclusive",
     "nodeName": "按天数分级",
     "branches": [
       {"when": "days > 7", "to": "n_director"},
       {"when": "days <= 7", "to": "end"}
     ]},
    {"nodeId": "n_director", "nodeType": "approval", "nodeName": "总监审批",
     "assigneeType": "role_global", "assigneeValue": "DIRECTOR"},
    {"nodeId": "end", "nodeType": "end", "nodeName": "结束"}
  ],
  "edges": [
    {"source": "start", "target": "n_manager"},
    {"source": "n_manager", "target": "gw_days"},
    {"source": "gw_days", "target": "end"},
    {"source": "n_director", "target": "end"}
  ]
}
```

### 4.5 节点类型

| 类型 | 说明 | 属性 |
|------|------|------|
| start | 流程起点 | — |
| end | 流程终点 | — |
| approval | 审批节点 | assigneeType, timeout, escalateTo, routingRules, countersign |
| gateway | 条件网关 | gatewayType(exclusive), branches[{when, to}] |

### 4.6 审批人解析策略

| assigneeType | 解析方式 | 适用场景 |
|-------------|---------|---------|
| `specific` | 直接指定员工 ID | 特殊情况指定审批人 |
| `dept_manager` | 向上遍历部门树找负责人 | 部门经理审批（默认） |
| `role` | 同部门内按角色查找 | 部门内特定角色审批 |
| `role_global` | 全局按角色查找 | 总监/总经理等全局角色 |
| `role_chain` | 按角色链从高到低匹配 | 逐级升级场景 |
| `initiator_level_match` | 返回第一个级别高于发起人的角色 | 高级别发起人自动跳过中间审批 |

### 4.7 条件评估

- **分支条件**：`"days > 7"`, `"amount >= 5000 && amount < 50000"`
- **路由规则**：节点级别的 `routingRules` 支持 `skipTo`、`jumpTo`
- **操作符**：`<`, `<=`, `>`, `>=`, `==`, `!=`, `equals`, `not_equals`, `contains`, `starts_with`, `in`
- **逻辑组合**：`&&`（与）, `||`（或）

### 4.8 流程生命周期

```
DRAFT(草稿) → SUBMITTED(已提交) → APPROVED(已通过)
                                 → REJECTED(已拒绝)
                                 → WITHDRAWN(已撤回)
                                 → CANCELED(已取消)
```

### 4.9 业务回调

流程完成后通过 Spring Event 触发回调（`WorkflowCallbackDispatcher`）：

| 回调 | 触发时机 | 典型操作 |
|------|---------|---------|
| `onApproved` | 所有节点通过 | 扣减年假额度、修改考勤状态、更新采购单状态 |
| `onRejected` | 任一节点驳回 | 释放额度、通知申请人 |

### 4.10 超时处理

| 操作 | 行为 |
|------|------|
| `escalate` | 超时后自动升级到 `escalateTo` 指定的更高级审批人 |
| `notify_only` | 仅发送超时通知 |
| `auto_reject` | 超时后自动拒绝 |

## 5. 安全架构

### 5.1 整体安全模型

```
┌──────────┐    ┌────────────┐    ┌──────────────┐    ┌──────────┐
│  请求     │───▶│ 限流拦截器  │───▶│ JWT 认证拦截器 │───▶│ 权限校验  │
│ (HTTP)   │    │ RateLimit  │    │ AuthInterceptor│   │ @Require │
│          │    │ (登录限流)  │    │ (Token 解析)   │   │Permission│
└──────────┘    └────────────┘    └──────┬─────────┘    └──────────┘
                                         │
                                    ┌────▼─────┐
                                    │ 请求属性  │
                                    │ empId/   │
                                    │ empName  │
                                    └──────────┘
```

### 5.2 认证流程

```
1. 用户 POST /login (username + password + captcha)
2. AuthService 验证账号密码 + 验证码
3. 验证通过 → JWT 生成 access_token (2h TTL)
4. 客户端存储 Token 在请求头 Authorization: Bearer <token>
5. AuthInterceptor 拦截每个请求：
   a. 从 Authorization 头提取 Token
   b. 解析 JWT 获取 empId
   c. 验证 Redis 中 Token 有效性
   d. 设置请求属性 empId/empName
   e. 校验角色/权限注解
6. Token 过期前 5 分钟 → 前端预刷新
```

### 5.3 JWT 结构

```
Header: {"alg": "HS256"}
Payload: {
  "empId": 1,
  "empName": "管理员",
  "tokenType": "access" | "refresh",
  "iat": ...,
  "exp": ...
}
```

### 5.4 权限校验流程

```
请求到达 → HandlerMethod 检查
├── @RequireAdmin → 验证用户角色包含 ADMIN
├── @RequireRole({"DEPT_MANAGER", "DIRECTOR"}) → 验证用户有任一角色
├── @RequirePermission("hr:leave:approve") → 验证用户权限标识
│   ├── Redis 查询 permissions:{empId}
│   ├── 命中 → 权限比较
│   └── 未命中 → PermissionResolverImpl 查询数据库
│       ├── sys_emp_role → sys_role → sys_role_menu → sys_menu.perms
│       └── 结果回填 Redis (2h TTL)
└── 无注解 → 放行
```

### 5.5 登录限流

- IP 级别限流：5 次/60 秒
- 基于 Redis 计数器（`rate:login:{ip}`）
- 超限返回 429 Too Many Requests

## 6. 数据架构

### 6.1 数据库设计

### 6.3 Entity 设计规范

```java
@TableName("hr_leave")
public class Leave {
    @TableId(type = IdType.AUTO)
    private Long id;

    // 业务字段
    private Long empId;
    private String leaveType;
    private BigDecimal leaveDays;

    // 逻辑删除（必须 String 类型）
    @TableLogic
    private String delFlag;

    // 审计字段（自动填充）
    @TableField(fill = FieldFill.INSERT)
    private String createBy;
    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;
    @TableField(fill = FieldFill.INSERT_UPDATE)
    private String updateBy;
    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;

    // 乐观锁
    @Version
    private Integer version;
}
```

## 7. 通信架构

### 7.1 前后端通信

- **协议**：HTTP/HTTPS RESTful
- **数据格式**：JSON
- **路径规则**：`/api/v1/{domain}/{resource}`
- **统一响应**：

```json
{
  "code": 0,
  "message": "操作成功",
  "data": {}
}
```

### 7.2 实时通信（WebSocket）

- **端点**：`ws://{host}/ws/notification?empId={empId}`
- **协议**：原生 WebSocket
- **事件机制**：
  - `wsClient.on(type, handler)` 订阅
  - 支持通配符 `*`
- **断线重连**：指数退避（1s → 2s → 4s → ... → 30s，最多 5 次）

### 7.3 模块间通信（Spring Event）

```
流程审批完成 → WorkflowCallbackDispatcher
    ↓ 发布 Spring Event
    ├── LeaveApplyEventListener → 更新请假状态 + 扣减年假额度
    ├── BusinessTripEventListener → 更新出差状态
    ├── OvertimeEventListener → 更新加班状态
    └── MessageEventListener → 发送审批结果通知
```

- 使用 `@EventListener` 监听业务事件
- 同步处理（Spring 默认）
- 替代传统 MQ 方案，适合单体应用内部解耦

## 附录

### A. 技术选型理由

| 选型 | 替代方案 | 选择理由 |
|------|---------|---------|
| MyBatis-Plus | JPA/Hibernate | 复杂 SQL 可控、学习成本低、贴近数据库 |
| 自研工作流 | Activiti/Flowable | 轻量无重量级依赖、业务定制灵活 |
| 自研认证 | Spring Security | 减少框架依赖、JWT 认证逻辑简单、避免 Security 复杂配置 |
| Spring Event | RabbitMQ/Kafka | 单体应用内部解耦足够、无额外运维成本 |
| Vue 3 + Element Plus | React/Ant Design | 国内生态成熟、开发效率高 |
| uni-app | Flutter/React Native | 一套代码同时出 H5 和小程序 |
| Tailwind CSS | SCSS/Less | 开发效率高、原子化 CSS、团队约定成本低 |
| EasyExcel | POI | 内存友好、API 简洁 |
