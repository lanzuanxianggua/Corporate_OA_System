# 核心业务代码实现总结

> 本文档总结了 OA 系统各核心业务模块的代码实现结构，标明每一层的代码位置和关键逻辑。
>
> **项目结构**：5 模块扁平分层（oa-common → oa-model → oa-mapper → oa-service → oa-web）
>
> **技术栈**：Java 17 + Spring Boot 3.4.5 + MyBatis-Plus 3.5.9 + Vue 3 + Element Plus
>
> **更新日期**：2026-06-21

---

## 一、系统架构概览

```
code/backend/
├── oa-common/        # 公共层：JWT、拦截器、统一响应 R<T>、异常、注解、工具类
├── oa-model/         # 数据模型：Entity（49个）、DTO（20个）、VO
├── oa-mapper/        # 持久层：48 个 MyBatis-Plus Mapper 接口（无 XML 文件）
├── oa-service/       # 业务层：Service 接口 + 实现类（41+ Service，含工作流引擎）
└── oa-web/           # Web 层：36 个 Controller + 配置类 + Flyway 迁移 + 启动类

code/frontend/src/
├── api/              # 35 个 API 调用文件（按业务域分）
├── views/            # 60+ 前端页面组件
├── router/           # Hash 路由 + beforeEach 守卫
├── store/            # Pinia：useUserStore + useThemeStore
├── layout/           # 主布局：SideMenu + TopBar + Content
├── components/       # 公共组件（ApprovalTimeline, FlowDesigner 等）
├── utils/            # Axios 封装、WebSocket 客户端、常量映射
└── types/            # TypeScript 类型定义
```

### 核心模块依赖关系

```
oa-common（无依赖）
    ↑
oa-model（依赖 oa-common）
    ↑
oa-mapper（依赖 oa-model）
    ↑
oa-service（依赖 oa-mapper）
    ↑
oa-web（依赖 oa-service，含启动类、Flyway 配置、WebSocket）
```

## 二、认证与权限体系

### 2.1 认证流程

前端登录 → AuthController 验证凭据 → JwtUtil 生成 accessToken + refreshToken → 返回前端存储 → 后续请求携带 `Authorization: Bearer <token>` → AuthInterceptor 校验

**关键代码位置：**

| 层级 | 文件路径 | 说明 |
|------|---------|------|
| Controller | `code/backend/oa-web/src/main/java/cn/oa/controller/AuthController.java` | `/api/auth/login`, `/api/auth/register`, `/refresh-token`, `/logout`, `/api/auth/change-password` |
| Service | `code/backend/oa-service/src/main/java/cn/oa/service/impl/AuthServiceImpl.java` | 自定义实现，不继承 ServiceImpl |
| 工具类 | `code/backend/oa-common/src/main/java/cn/oa/common/utils/JwtUtil.java` | JWT 签发与验证 |
| 拦截器 | `code/backend/oa-common/src/main/java/cn/oa/common/interceptor/AuthInterceptor.java` | Token 校验、权限注解解析、在线状态维护 |
| 限流 | `code/backend/oa-common/src/main/java/cn/oa/common/interceptor/RateLimitInterceptor.java` | 登录接口限流 |
| 配置 | `code/backend/oa-common/src/main/java/cn/oa/common/config/WebMvcConfig.java` | 注册拦截器、CORS（allowedOriginPatterns） |

### 2.2 权限模型（RBAC）

| 组件 | 文件路径 | 说明 |
|------|---------|------|
| 权限注解 | `code/backend/oa-common/src/main/java/cn/oa/common/annotation/RequirePermission.java` | Controller 方法上声明 `@RequirePermission("hr:leave:create")` |
| 角色注解 | `code/backend/oa-common/src/main/java/cn/oa/common/annotation/RequireRole.java` | 按角色限制访问 |
| 管理员注解 | `code/backend/oa-common/src/main/java/cn/oa/common/annotation/RequireAdmin.java` | 仅管理员可访问 |
| 当前用户 | `cn.oa.common.context.UserContext`（ThreadLocal） | 拦截器解析 Token 后存入，Controller/Service 中 `UserContext.get()` 读取 |
| 操作日志 | `code/backend/oa-common/src/main/java/cn/oa/common/annotation/OperationLog.java` | 配合 OperationLogAspect 记录操作轨迹 |

**权限码格式**：`{domain}:{resource}:{action}`，如 `hr:leave:create`、`attendance:list`

### 2.3 静态角色-权限映射

AuthInterceptor 中 `ROLE_PERMISSIONS` Map 定义了 USER 角色的静态权限集：

```java
ROLE_PERMISSIONS.put("USER", Set.of(
    "attendance:checkin", "attendance:list",
    "leave:apply", "leave:list",
    "notice:list", "notice:read",
    ...
));
```

## 三、自研工作流引擎

工作流引擎是本系统的核心创新点，支持图结构（Graph）流程定义、4 维分级路由、动态审批人解析、业务回调。

### 3.1 核心文件

| 层级 | 文件路径 | 说明 |
|------|---------|------|
| 引擎 | `code/backend/oa-service/src/main/java/cn/oa/service/workflow/WorkflowRuntimeEngine.java` | 轻量级图工作流运行时，解析 schemaVersion=2/3 的定义，执行节点流转和审批人路由 |
| 图模型 | `code/backend/oa-service/src/main/java/cn/oa/service/workflow/WorkflowGraph.java` | 图结构模型（nodes + edges），存储节点关系和路由配置 |
| 回调 | `code/backend/oa-service/src/main/java/cn/oa/service/workflow/WorkflowCallback.java` | 业务回调接口（Spring Event 事件驱动） |
| 分发器 | `code/backend/oa-service/src/main/java/cn/oa/service/impl/WorkflowCallbackDispatcher.java` | 工作流状态变更时分发回调事件到各业务模块 |
| Controller | `code/backend/oa-web/src/main/java/cn/oa/controller/WorkflowController.java` | `/api/workflow`，定义管理、任务处理、抄送、委派 |
| 判分器 | `code/backend/oa-service/src/main/java/cn/oa/service/impl/RoleResolverImpl.java` | 角色链解析、发起人级别匹配 |

### 3.2 数据模型

| 表 | Entity | Mapper | 说明 |
|----|--------|--------|------|
| `wf_process_definition` | `WfProcessDefinition.java` | `WfProcessDefinitionMapper.java` | 流程定义（nodeConfig 存图 JSON） |
| `wf_process_instance` | `WfProcessInstance.java` | `WfProcessInstanceMapper.java` | 流程实例（每次发起的审批） |
| `wf_task` | `WfTask.java` | `WfTaskMapper.java` | 任务节点（审批任务） |
| `wf_cc_record` | `WfCcRecord.java` | `WfCcRecordMapper.java` | 抄送记录 |
| `wf_delegation` | `WfDelegation.java` | `WfDelegationMapper.java` | 审批委派配置 |

所有表定义均在：`code/backend/oa-model/src/main/java/cn/oa/entity/`，对应 Mapper 在 `code/backend/oa-mapper/src/main/java/cn/oa/mapper/`

### 3.3 审批链与分级路由

| 功能 | 路径 | 说明 |
|------|------|------|
| 审批链 | `Flyway V1012__tiered_workflow_approval_chains.sql` | amount/days/hours/role_level 4 维路由 |
| 种子数据 | `Flyway V1011__workflow_graph_seeds.sql` | 7 种流程预置定义（请假/出差/外出/加班/报销/采购/借款） |
| v3 运行 | `Flyway V1013__workflow_schema_v3_custom_runtime.sql` | 自定义运行时配置 |

**4 维分级路由规则**：按金额（amount）、天数（days）、小时数（hours）、发起人职级（role_level）自动匹配不同的审批链，实现"小事少批、大事严审"。

### 3.4 业务回调机制

工作流状态变更 → Spring Event 发布 → 各业务 Service 监听 → 更新业务表状态

当前支持的回调模块：
- **出差**（OaBusinessTrip）
- **加班**（OaOvertime）
- **采购**（OaPurchase）

回调代码：`code/backend/oa-service/src/main/java/cn/oa/service/impl/WorkflowCallbackDispatcher.java`

### 3.5 前端流程设计器

| 文件 | 说明 |
|------|------|
| `code/frontend/src/views/oa/workflow/definition/index.vue` | 流程定义管理页面 |
| `code/frontend/src/components/flow-designer/` | FlowDesigner 组件（基于 @vue-flow/core） |

**通用审批流程：**
1. 员工提交申请 → 业务 Controller 接收 → Service 保存业务记录 + 调用 WorkflowService 创建流程实例（PENDING）
2. WorkflowRuntimeEngine 解析定义 + 按 4 维规则路由 → 生成 WfTask（审批节点）
3. 审批人处理（同意/驳回/转办/加签） → WorkflowCallbackDispatcher 发布 Spring Event
4. 业务模块 Event 监听器 → 更新业务表状态（APPROVED/REJECTED）+ 触发后续逻辑（如扣减假期余额）
